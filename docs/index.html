Local or iCloud Dynamic Backups

Choose per iPod

Choose Local or iCloud in Dynamic Backup Settings for a directly connected, mounted iPod with a confirmed serial number. Each destination keeps its own baseline and history. Network Dynamic Backup remains unavailable.

Share unchanged data

The first backup creates a baseline. Reconnect checks create a snapshot only when files change, storing new content in Shared Backup Data. Keep that folder with the snapshots. Reformatting keeps earlier versions and establishes a new baseline.

Understand cloud storage

iCloud uses your chosen iCloud Drive folder; macOS can cache it locally. Missing cloud data stops an update instead of triggering a replacement full backup. Upload status comes from macOS. No extra encryption is added. Automatic retention is local-only; manage cloud deletion in Finder. Live account transfer still needs verification.

The connection makes a difference.

Direct USB / FireWire

Normal-mode firmware restoration uses Apple’s installed updater with matching firmware and live device checks. FireWire needs a functioning driver and the right power/cable setup. Detection alone does not establish that a restore will complete.

Over the network

The main Mac prepares firmware and the filesystem; the bridge forwards checked device I/O. The disk engine needs a valid existing firmware/data map. Classic, nano 2–7, shuffle, DFU and entirely blank network disks need additional protocols.

Mac or Windows format

Use only the format reported as supported by the live iPod. Shuffle uses Windows/FAT. Other models offer HFS+ or FAT32 only where allowed; a missing capability is not conversion approval. APFS and exFAT are not restore targets.

Before you connect

Do backups, transfers and photo sync work on every model?

Backups need readable mounted storage and a stable device identity. Media writers and artwork/photo profiles are model-specific; a category appearing in the library is not a guarantee that every item can be synced. Cross-generation conversion applies only to implemented direct-connection workflows. Network backup activation requires a complete matching-serial backup; network Dynamic Backup, media edits and cross-generation conversion remain incomplete.

What happens with Rockbox or click-wheel games?

Rockbox workflows require a matching implemented target, compatible build and the model’s bootloader prerequisites. Network Rockbox writes are unavailable. Game detection, archiving and importing .ipg files do not grant Apple game authorization. The game storefront is hidden in this beta.

What is different about Nano 2 recovery?

Nano 2 has boot-ROM and NOR recovery modes. This beta has no verified DFU/NOR bootstrap for them. If the Apple bootloader still works, disk mode may allow a normal matching restore. An original device-specific NOR backup is not interchangeable with a dump from another iPod.

What should I know before testing the beta?

The app is ad-hoc signed and not Apple-notarized. Beta preferences are separate, but files under Documents/iRestore are shared with the regular app. Run one version at a time and keep independent backups. Byte readback is not proof of successful boot. If a restore stops after writing, inspect the iPod and retain its log before another attempt.

Where do these labels come from?

This is a release-specific implementation chart, reviewed against the beta’s model identification, media capabilities, restore format policy, recovery loader catalog and network disk-engine profiles.
